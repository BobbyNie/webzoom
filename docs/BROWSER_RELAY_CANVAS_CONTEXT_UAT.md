## 确认的上下文初始化问题与修正

`Viewer.reset()` 会先调用 `clear()`；旧 `clear()` 首次调用 `getContext('2d')` 时未提供任何设置。浏览器在第一次取得上下文时就固定创建属性，后来绘制时补传 `alpha:false` 不会重建上下文，因此旧版事实上没有始终使用期望的不透明视频画布。

现在首次清空、观众绘制、共享者预览都一致声明 `{alpha:false, willReadFrequently:false}`。这些画布是写入视频帧的表面，产品本身不读回像素；显式声明写入用途也避免了 Chromium 对“未指定”读回设置的 CPU 回退启发式。这只是绘制提示，**不是强制 GPU 或硬件加速的保证**。

为核实浏览器实现，本轮只读取得公开 Chromium **155.0.8059.39** 对应的 `base_rendering_context_2d.cc`：该版本在 `willReadFrequently` 内部值为未指定、且满足读回阈值时可调用 `DisableAcceleration()`。与运行时警告相互印证，但仍须通过行为验证，不能把源码推理当作长测通过。

两项新回归在产品修正前均失败、原 16 项相关检查通过；修正后全套 **89 项单元测试通过**，类型检查及前端构建通过。回归特别检查了“第一次清空”而不只是随后绘制，防止设置再次加得太晚。

**验证此改动时保持原像素检测方法不变**，没有改成只检查统计数字、缩小观众数、换静态源、替换采集/编解码器或降低质量门槛。六观众五分钟验证只作为短测，不替代三十分钟验收。
