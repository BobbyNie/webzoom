## 方案边界

保留普通网页：共享者通过 WSS 上传压缩后的 VP8，服务器供给网页转发节点，再由 WebRTC DataChannel 向下游转发；每个节点最多带三位观众，只有一层转发。不安装插件/EXE，不接入原生 UDP 组播，不引入公网 STUN/TURN，也不新增外部访客授权或对外开放网络入口。

跨楼、外包公司的实际可用性需要分别验证站点可达、身份授权、同伴路径和服务器回退预算。自动分配浏览器节点不等于自动获取对方网关；内网候选地址也不能证明两人位于同一办公室或证明节省了 WAN 流量。

## 当前工作树中的能力

- 默认入会门槛调整为 64 位观众 + 1 位共享者。显式配置的更低上限继续生效；不代表已验证 64 台电脑或百人容量。
- 新人入会、供流计划更新时保留同一共享轮次中的健康连接；允许保留连接完成原代次的协商，保留已发送/已应答标记以拦截重放。
- 同伴失败时可尝试有空位且尚未失败的现有节点；最多记录三位失败来源，无法继续时申请受带宽预算限制的服务器回退，预算不足则等待。新的共享轮次清理失败来源记录。
- 成员进出导致的计划更新不重置同一来源的故障计时，避免卡住的观众一直得不到换源。真正更换来源时才重新给予连接建立时间。
- 发送端有高/低水位背压；拥堵下游恢复后等待关键帧，不拖停健康下游。计算积压时包括分片头部，关键帧请求有节流。
- 页面切前后台时上报可见状态；后台不等于已断流。恢复前台请求关键帧。媒体回调也检查控制授权，不能因后台计时器暂停而绕过授权继续转发。
- 看板区分正常服务器供流和故障回退，并显示相邻上报间的平均 Mbps。缺少样本、报告过期或供流代次切换时不复用旧速率。这是接收端自行上报，不是网卡/WAN 实测。
- WebSocket 重连间隔采用有限指数退避和抖动。
- README 已纠正“完全不使用 WebRTC”的旧描述，明确默认服务器模式与可选网页同伴模式的区别。

## 本次实际完成的验证

- 前端 54 项单测通过，TypeScript 类型检查及生产构建通过。
- `go test ./internal/meeting ./cmd/webzoom` 通过。
- `go vet ./cmd/... ./internal/...` 通过。
- 真实本机 Chromium/DataChannel 分流联测 7/7 通过（约 1.5 分钟）：
  - 一带三、转发节点退出后的恢复、会议结束后的停止。
  - 网络能力阻断时，有预算则服务器回退，无预算则等待。
  - 六会话中途入会，既有观众的原生连接数量不增加；真实连接关闭后换到另一转发者，服务器接收量仍为零，健康兄弟节点不重建。
  - 仅停止统计报告时，画面仍流动，看板标记过期；恢复报告后状态恢复。
- 另增加四轮停止/重新共享、旧连接释放和 WSS 短暂离线后自动重新入会的真实浏览器检查；后者不等于物理断网或 ICE 路径恢复。
- 新增 Go 单测验证 64 位观众的调度：预算充足时 16 个转发节点 + 48 个同伴接收者；20 Mbps 的测试预算下只有 1 个节点 + 3 个同伴，其余等待，不绕过预算；第 65 位观众被拒绝。这项调度单测不是压力测试。另有本机 16/32/64 会话容量采样、持续共享和两小时逻辑时钟回归，结果及复跑入口见 [容量采样记录](BROWSER_RELAY_CAPACITY_UAT.md)；不能据此宣称 64 台真实电脑流畅。
- 单测另覆盖保留连接与旧代次协商、信令重放、三次失败来源上限、失败记录清理、回退带宽限制、可见状态验证、速率采样边界、媒体回调检查授权、独立下游背压、旧代次帧忽略，以及供流计划频繁更新时仍能按时发现断流。
- 普通会议/小窗/批注/SSO 62 项浏览器回归全部通过（约 2.3 分钟）。
- 后续本地容量 16/32/64 会话 3/3 通过；64 会话为 16 个转发节点和 48 个同伴，但最低观众平均帧率约 3.56 fps，不能认定流畅。5 位观众的真实持续共享另运行 600.10 秒通过；详细数据、启动丢帧和限制见容量采样记录。
- 已检查实际生成的分流看板截图：正常供流、换源后的来源、过期统计和窄屏布局由联测覆盖。

浏览器验证只启动本机回环测试站点和虚拟身份服务，没有使用公司账号或公司环境。截图在 `web/test-results/browser-relay/`，属于本地测试产物，不是公司现场证据。
