# 内网页面分发 LAN 客户端（r2）

## 交付边界

- 独立分支 feature/lan-udp-relay；不改正式 main / v* / latest。
- 新镜像包含本次源码交叉编译的 Windows 64 位安装模板。CI 将镜像内模板与同次 Windows 构建、检查通过的模板逐字节比较，不在运行时访问 GitHub。
- 管理员只搬运一次镜像。所有同事登录同一内网站点，从页面下载安装，服务器进程在内存中按可信 PUBLIC_URL、LAN_CLIENT_PORT 缩小模板权限。无需可写根目录或新增 PVC。
- 页面首次进入自动检查并显示安装提示；点击才下载，不重复强制弹下载、不自动运行 EXE、不修改 Chrome 管理策略。

## 管理员一次性配置

沿用现有部署的 SSO、管理员、CA、PVC、Route 和安全设置。只原子更新镜像以及需要的 LAN 开关/端口；先备份现场配置，无在开会议才更新。不要重新 apply 旧 YAML。

```text
LAN_RELAY_ENABLED=true
LAN_CLIENT_PORT=<公司 IT 已批准的 1024–65535 UDP 端口>
```

`PUBLIC_URL` 沿用现有可信精确 HTTPS 来源。所有试点电脑从同一站点下载使用同一端口，端口未知不得猜。`LAN_CLIENT_DIR` 在镜像中为 `/app/lan-client`，一般不必设置。

- GET /api/lan/client：登录态安装信息、配置状态、网站专用包 SHA-256，不返回内网网卡/文件路径。
- GET /api/lan/client/setup.exe：登录态固定文件下载，attachment、no-store、nosniff；无任意路径浏览，不允许跨站发起。未配置端口/无模板/无效网站时503，绝不发出宽权限包。
- 网站专用包与 GitHub 通用模板校验和不同是预期行为：仅变更配置与扩展站点作用域，PE stub/native 二进制不变。当前不支持对 overlay 包直接追加 Authenticode 签名，仍为未签名获批试点。

## 同事操作

1. 登录页面 → 下载 Windows 安装程序。
2. 打开下载文件 → 安装 / 修复，网站及端口已填好。
3. Chrome 插件：优先 IT 企业统一下发；获批本地试点按安装器两个按钮打开扩展文件夹及 Chrome 扩展页，再加载已解压插件。禁止绕过公司策略。
4. 刷新页面 → 自动检查 → 启用局域网分流。

## 验证

Go 测试覆盖：模板配置化/确定性/不修改模板、认证、撤销会话、可信来源、下载头、SHA-256、HEAD、跨站拒绝、禁用/缺端口/缺文件失败关闭。
浏览器测试覆盖：首次访问引导、仅点击下载、缺端口管理员提示、本机检查与显式启用分离、原有媒体与重选；真实 MV3/真实 native 集成增加首页诊断桥测试。诊断不发广播，不假报跨机成功。

公司多机广播、真实视频/出口、长期及容量验收仍需现场完成。CI 或发布成功都不表示 OCP 已升级。
