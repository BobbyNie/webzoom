# 共享画面批注（浏览器版）

## 使用方法

1. 会议发起人开始共享；发起人在共享期间始终可使用批注。
2. 在参与者列表中，发起人点击某人的“允许批注”。授权只针对该会议中当前已连接的参会人。
3. 被授权者在共享画面下方选择“画笔”或“指示光标”，可选红、蓝、绿、黄四种颜色。
4. 画线会同步到其他参与者；指示光标显示登录者姓名。迟到者可看到当前共享阶段已有的画线。
5. “观看”关闭自己的交互工具，但仍能看到其他人的标注。
6. “清除我的”仅删除自己的画线；只有会议发起人可以“清除全部”。
7. 发起人点击“撤销批注”后，该参会人不能再提交标注。已有画线保留，必要时由发起人清除。

批注权限与“共享屏幕权限”、独立 `/admin` 管理员权限是三件不同的事。
转交共享权不会自动授予批注权；主持人也不需要全局管理员身份。

## 明确边界

这是 WebZoom 网页内的叠加图层，不是远程控制或系统桌面绘图：

- 共享者在 WebZoom 网页预览中可以看到标注；若正在看原来的 Excel/PPT 窗口，那个窗口不会出现标注。
- 不会修改原文件，也不把批注烧录进 VP8 视频。
- 无需浏览器插件、原生辅助程序或管理员安装。
- 同步依据画面归一化坐标，避免不同窗口大小、黑边和全屏造成偏移。
- 开始、停止、转交共享或共享者断线会清除旧阶段的画线。
- 授权可跨共享阶段保留，但参会人离开、断线或连接被替换后需要重新授权。
- 指示光标不持久化；最后一次更新后约 1.8 秒自动消失，慢连接可丢弃指示更新。
- 画线和授权只保存在内存，不跨会议结束、服务重启保存；本版没有撤销/重做、导出、文字或桌面窗口叠加。

## 服务端安全与容量保护

- 授权/撤销复用现有认证、同源 Origin 和 CSRF 校验，仅允许固定会议发起人操作。
- 服务端独立检查每条批注命令的当前连接、授权、共享状态、epoch 和 generation；隐藏按钮不是安全措施。
- 署名从已认证的连接取得，客户端不能伪造其他人的署名。
- 坐标必须是有限数且在 `[0,1]` 内，颜色限定为四种，笔划 ID 长度和格式受限，片段必须顺序递增。
- 每条命令最多 32 个点；单笔最多 512 个点；每房间最多 128 笔、8192 个存储点。
- 每房间共享 60 条/秒批注更新预算（画笔、光标和清除合计）。光标超额静默丢弃；画笔/清除超额显示拒绝提示。大量用户同时移动光标可能挤占画笔预算；这不是百人同时绘制能力承诺。
- 浏览器通常每 100 毫秒发送一批，最多 16 个点，并合并鼠标事件。单笔浏览器侧约 500 个点后要求抬起继续。
- 既有 WSS 限制仍为每连接每秒 20 条控制消息、单条 4096 字节。批注与 clock 等控制消息共享这个连接限制。
- 光标队列达到 8 个控制事件时可丢弃；画线和状态使用现有可靠事件队列和慢连接断开策略。

这些限制可保护资源，但不替代目标环境容量测试。批注 JSON 不计入当前 `/admin` 的媒体流量统计；真实网络还包含控制消息和 TLS/WSS 开销。
本功能不会解决此前讨论的 OCP 媒体带宽问题，也没有实现 LAN UDP 广播方案。

## 部署和验收

本功能不新增 SSO client、OIDC 角色、环境变量或 OCP 权限。前后端必须作为同一版本构建并发布，不能只替换静态网页。
不要把本地测试通过误认为目标 OCP 已部署；发布仍需按现有流程构建镜像并在 UAT 验收。

UAT 建议至少准备三个不同账号，检查：

- 未授权者只能观看；发起人授权后可画线、显示署名指示。
- 撤销后后端确实拒绝更新；自己的清除不影响别人，参会人不能清除全部。
- 迟到加入、浏览器窗口缩放和全屏后坐标保持正确。
- 转交、停止、重新共享后不残留旧画线；被转交共享权者并未自动获得批注权限。
- 在实际 Chrome/Edge、真实屏幕选择器与公司 SSO 上跨令牌周期使用。
- 目标人数下同时移动/绘制，观察流畅度、拒绝提示和实际 OCP 网络指标。

本地验证记录见 `docs/VERIFICATION.md`。以上 UAT 项目是待验收清单，不是已经执行的结论。

测试镜像交付、现有 OCP UAT 更新、手工验收与回退步骤见 `docs/ANNOTATION_UAT.md`。
