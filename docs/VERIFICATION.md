## 3. 1000 名模拟听众的短时测试

执行命令：

```sh
WEBZOOM_LOAD_SMOKE=1 go test -count=1 -run TestCapacitySmoke -v ./internal/loadgen
```

规模：5 场会议，每场 1 名共享者和 200 名听众，共 1005 条认证 WSS 连接。
数据：每路目标 6 Mbps、30fps 的合成封包。合成内容不是可解码 VP8 视频。
环境：同一台主机内的 TLS/WSS。没有经过 Nginx、OpenShift Route 或物理网卡。

最后一次本地执行结果：

```json
{
  "mode": "synthetic-relay-only",
  "duration_seconds": 10.022724291,
  "frames_sent": 1492,
  "frames_received": 298400,
  "bytes_received": 7469548800,

```

服务端拒绝入队的媒体帧计数为 0。
上述收帧字节对应约 5.96 Gbps 的环回媒体封包吞吐，不含 TLS/IP 开销。
100ms 是接收延迟直方图的分桶上界，不是精确的延迟值。
这不是采集到显示的端到端延迟，也不是物理网络出口能力。
测试持续约 10 秒，不是 30 分钟。帧数受定时器和结束边界影响。

**此结果不能证明 5×200、1080p30、画面延迟 p95 ≤1 秒的目标已达标。**

## 2026-10-12：活跃登录续期修复

根因包含三个部分：登录后没有保存刷新令牌；浏览器 Cookie 保留初次期限；WSS 计时器固定使用初次期限。
因此，Keycloak 的短期令牌到期后，持续投屏也会被判定为登录失效。

本次先观察失败测试，再实现并验证各增量：

- 服务端保存并串行刷新令牌。校验新 ID token 的签名、issuer、audience、subject 和可选 nonce。
- 拒绝刷新、异常身份和过期令牌撤销会话。临时 503 不立即撤销仍有效的会话。
- HTTP 保活要求有效会话、同源 Origin 和 CSRF token。成功后更新安全 Cookie。
- WSS 在旧期限触发时重新读取当前期限。有效续期不关闭媒体连接。
- 共享者和听众参加会议时自动保活。闲置首页不无限刷新。
- 前端更新期限时不重建媒体 effect。退出、真正到期和固定 8 小时上限仍生效。
- 并发刷新、刷新令牌轮换、刷新期间退出、闲置标签页观察其他标签页续期均有回归测试。

2. `go test -tags testtools ./cmd/testserver` 通过。
