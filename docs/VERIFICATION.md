# 验证记录

验证日期：2026-10-08。
本记录描述本地开发环境的实际结果，不是生产容量合格证。

**交付状态：首版核心功能、部署工件和测试工具已实现。正式容量验收未完成。**

原计划要求先通过画面原型和容量门槛，再完成会议功能。
本次完成了本地 VP8 原型和合成转发测试，但没有完成目标内网的正式质量门槛。
会议功能和部署工件已经继续实现。生产发布仍必须经过下列剩余验收。

## 1. 环境与范围

- 开发宿主机：macOS，ARM64。实际 Go 工具链报告 `go1.26.8 darwin/amd64`。
- 容器环境：Docker Desktop。本次验证不代表目标 OpenShift 节点的性能。
- 浏览器自动化：Playwright 1.64.0 提供的无头 Chromium。
- 测试身份服务：本地 HTTPS OIDC 服务，使用实际签名的 JWT。
- 浏览器采集源：动画 Canvas，实际执行 VP8 编码、WSS 传输、VP8 解码和 Canvas 显示。
- 没有连接真实公司 Keycloak，没有修改或部署真实 OpenShift 集群。

浏览器测试用例为自签名测试证书设置了 `ignoreHTTPSErrors`。
这只存在于测试配置。生产代码没有关闭证书验证的开关。
Go TLS 和 Nginx 代理测试使用明确受信任的测试 CA，不跳过校验。
测试日志中的浏览器 TLS 探测告警不能作为真实证书验收结果。

### Go 覆盖的主要行为

- 视频封包验证，以及按关键帧恢复的有界队列。
- 慢听众队列不阻塞正常听众。
- 身份认证、会话到期、CSRF、WSS Origin 和未授权连接。
- OIDC state、PKCE、nonce、签名、issuer、audience 和回调重放拒绝。
- 拒绝发现文档中的 HTTP 授权、令牌和 JWKS 地址。
- 主持人权限、共享者权限、旧共享编号、重复序号和过期会议。
- 会话撤销、关键帧请求合并和实际画质指标。
- Secret 文件读取、互斥配置和大小限制。
- 负载工具的 TLS 认证、IVF 解析，以及只读加入现有会议。

### 七项浏览器测试

1. 登录、创建、共享、晚加入、转交和结束会议。
2. 匿名访问要求登录，并保留会议返回地址。
3. 用户取消采集授权后，会议保持未共享状态。
4. 共享者退出应用后，听众隐藏旧画面并显示共享中断。
5. 听众断线重连后恢复画面，浏览器停止共享后清空画面。
6. 禁用 `requestAnimationFrame` 后仍能编码屏幕帧。
7. 共享者媒体连接断开后明确显示“共享已中断”，重新共享后恢复。

测试禁止调用 `getUserMedia` 和 `RTCPeerConnection`，并检查采集参数中的 `audio:false`。
单元测试还验证了意外音频轨道会触发停止，而不是继续传输。
网络测试收集到的业务请求均为本地 HTTPS/WSS。
真实网关抓包、真实权限弹窗和目标浏览器的音轨检查仍需要执行。

## 3. 1000 名模拟听众的短时测试

执行命令：

```sh
WEBZOOM_LOAD_SMOKE=1 go test -count=1 -run TestCapacitySmoke -v ./internal/loadgen
```

规模：5 场会议，每场 1 名共享者和 200 名听众，共 1005 条认证 WSS 连接。
数据：每路目标 6 Mbps、30fps 的合成封包。合成内容不是可解码 VP8 视频。
环境：同一台主机内的 TLS/WSS。没有经过 Nginx、OpenShift Route 或物理网卡。

最后一次本地执行结果：

```json
{
  "mode": "synthetic-relay-only",
  "duration_seconds": 10.022724291,
  "frames_sent": 1492,
  "frames_received": 298400,
  "bytes_received": 7469548800,
  "sequence_gaps": 0,
  "unexpected_disconnects": 0,
  "receive_p95_upper_ms": 100,
  "render_latency_verified": false
}
```

服务端拒绝入队的媒体帧计数为 0。
上述收帧字节对应约 5.96 Gbps 的环回媒体封包吞吐，不含 TLS/IP 开销。
100ms 是接收延迟直方图的分桶上界，不是精确的延迟值。
这不是采集到显示的端到端延迟，也不是物理网络出口能力。
测试持续约 10 秒，不是 30 分钟。帧数受定时器和结束边界影响。

**此结果不能证明 5×200、1080p30、画面延迟 p95 ≤1 秒的目标已达标。**

## 4. TDD 记录

实现按失败测试、最小实现、回归测试和 Git 提交进行。
本次收尾阶段明确观察了以下失败，再完成修复：

- OIDC 接受 HTTP discovery endpoint，三个拒绝测试均失败。增加 HTTPS 校验后通过。
- 屏幕编码依赖页面动画时钟。禁止该时钟时，编码帧数为 0。
  改用 `MediaStreamTrackProcessor` 读取屏幕帧后通过。
- 共享者断线后，听众显示“等待共享”，不符合明确中断提示。
  增加断线状态识别后通过，并验证重新共享可以恢复。

其他已验证增量见 Git 历史，包括协议、认证、界面、负载工具、Secret 和指标。
新增测试不等于穷尽全部风险。剩余验收不能省略。

## 5. 发布前必须完成的验收

1. 对接实际 Keycloak。验证配置、私有 CA、PKCE 和令牌有效期。
2. 使用真实 Chrome 和 Edge。验证系统屏幕选择、取消、停止及无音频采集。
3. 验证切换窗口、隐藏标签页、最小化和锁屏时的采集行为。
4. 通过真实 Nginx 或 OpenShift Route 执行协议抓包。
5. 在目标 OpenShift 执行服务端 dry-run、SCC 检查、Route 超时检查和部署验证。
6. 按 `docs/CAPACITY.md` 运行五场各 200 名听众，持续 30 分钟。
7. 每场抽样真实浏览器解码。保存采集到显示的延迟原始样本、分辨率和实际帧率。
8. 验证并发转交、丢失关键帧、网络中断、晚加入，以及会话到期的交错场景。
9. 在受控网络拥塞下检查恢复、降级标识、RSS 和所有层的缓冲是否有界。
10. 确认慢听众不会拖慢其他会议，并记录单路编码对同场其他听众的影响。
11. 扫描最终应用镜像和代理镜像，完成组织要求的安全与许可证审查。

正常质量验收失败时，记录具体瓶颈并修改资源或设计。
不得用自动降级、只建立连接、合成数据或环回吞吐替代正式验收。

## 6. 已知产品限制

- 会话不刷新令牌。有效期取 ID token、access token 和 8 小时上限中的最早时间。
- 没有 Keycloak backchannel logout。远端撤销最迟在本地期限到达时生效。
- 服务重启会丢失会议和会话。当前没有多实例、持久化或无中断升级。
- 每个身份在同一会议只允许一个媒体连接。
- 突然断网的检测受心跳和网络超时影响。不能保证零时间检测静默网络故障。
- 界面延迟为时钟校准后的估计值，不是实验室验收数据。
