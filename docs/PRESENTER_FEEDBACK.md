# 共享者反馈小窗（纯 Web UAT）

分支：`feature/presenter-feedback-pip`。本功能无需 EXE、浏览器扩展、管理员安装或新 SSO Client。
仅发布独立 UAT 预发布，不修改 main、稳定版本或公司现有部署。

## 一、能做什么

1. 共享者选择屏幕、业务窗口或浏览器标签页开始共享。
2. 在 WebZoom 点击“打开反馈小窗”。这是浏览器原生 Document Picture-in-Picture，不是普通网页弹出窗口。
3. 主持人给参会者授权后，参会者使用“画笔”或“指示光标”。小窗显示共享画面上的笔迹和带姓名的光点。
4. 共享者切回业务应用后看置顶小窗，不用切回会议页面。不会移动或控制共享者的鼠标。
5. “完整画面”显示全景；“跟随指示 ×2”放大最近的指示位置并用位置示意图保留方向；“仅标注”去掉业务视频，只显示位置网格、笔迹与光点。
6. 小窗可以由用户拖动、调整大小。关闭小窗不停止共享，可以重新打开；小窗也提供“停止共享”。

关闭旧实验版 Windows 助手，不要同时运行。该分支取消了主界面的助手配对入口；旧源码及后端兼容性测试仍保留，但此 Release 不包含 EXE，也不依赖助手接口。

## 二、不能承诺的效果

- **不会把圈或远程光标直接画到原 Excel/PPT/任意桌面应用上。** 它们显示在小窗的画面中。
- **整屏共享可能再次捕获小窗**，出现画面套娃、遮挡，或让参会者也看到小窗内容。浏览器没有可依赖的通用“排除本小窗”能力；本实现没有伪称做到排除。
  - 最佳实践：共享业务窗口/标签页；或者把小窗放到未共享的第二块显示器。
  - 单屏必须整屏共享时：测试实际浏览器行为；如出现套娃，切到“仅标注”。这个模式没有业务图像，只能辅助定位，是降级而非等价体验。
  - 整屏时小窗里的内容和姓名可能被其他参会者看到，不应视为私密通知。
- 笔迹按画面位置记录，不会自动跟随滚动的单元格、段落或窗口；换页、滚动后清除旧笔迹。
- 本地预览比远端画面更及时。快速滚动时对方可能仍在指上一帧；请暂停操作确认，不承诺逐帧语义对齐。
- 多人同时指示时放大视图优先跟随最新活跃光点。光点短暂过期后消失；不接管系统鼠标。
- 不保证公司受管浏览器、VDI、锁屏、系统安全桌面或特殊全屏模式下的置顶行为；必须公司实机 UAT。
- 不新增视频到 OCP 的上行/下行连接，但本机需要额外渲染预览，可能增加 CPU/GPU 消耗。这不是 UDP/LAN 转发或视频带宽优化方案。

## 三、实现与安全边界

- 复用现有 capture MediaStream；小窗是本机 `<video>` + 只读 SVG 标注与姓名指示点。没有第二次采集授权、第二路编码或额外媒体 WebSocket。
- React portal 把受控 UI 渲染在浏览器 PiP document；引用现有同源 CSS，不插入脚本字符串，不放宽 CSP。
- 权限仍由现有服务端执行。打开小窗不会授予画笔权限，参会者也不能通过小窗发起远程控制。
- 激光笔过期计时使用可见 PiP document 的定时器。销毁、断线、停止共享、转交共享权、结束会议会关闭小窗并释放 DOM/video 引用；关小窗不会停止共享 track。
- 处理打开失败和异步打开期间停止共享的竞争情况。不支持 API 时明确提示，不用不能保证置顶的普通窗口冒充。
- 不增加环境变量、Route、端口、SSO 回调、CA 设置、Secret 或 OCP 权限；服务端原有单副本/Recreate 约束不变。

## 四、测试与必须完成的公司 UAT

自动测试使用真实 Chromium Document PiP 窗口和本机 Go HTTPS/OIDC 测试服务，屏幕源使用合成 canvas，并非真实桌面捕获。
覆盖：不同账号批注/姓名指示点、坐标映射、缩放/小窗尺寸、清除/撤权、仅标注、关闭重开、停止/转交/结束/断线、打开失败/不支持、迟到的打开结果、丢失清除事件后的指示点过期。原有会议/会话续期/管理员测试也必须通过。

公司 UAT 至少两台电脑、两个账号：

- [ ] 浏览器可信 HTTPS，点击按钮能够打开并置顶；切到业务应用后仍可见。
- [ ] 共享业务窗口、业务标签页分别确认图像、画笔、光点及姓名正确。
- [ ] 整屏测试是否捕获小窗、是否套娃；需要时改用第二屏或仅标注，不以截图自动测试代替该验证。
- [ ] 100% / 125% / 150% 缩放及不同长宽比，小窗全景/放大/边缘位置正确。
- [ ] 主持人授权/撤权正确；仅有共享权但无批注权的人不会因此获得画笔。
- [ ] 不移动共享者鼠标，不拦截原应用输入。
- [ ] 停共享/转交/结束/掉线/退出后小窗关闭；重开不残留旧会议视频。
- [ ] 真实 SSO 续期、网络重连正常；低性能机器检查 CPU/GPU 和帧率。

## 五、为什么没有改成透明桌面覆盖

截至 2026-10-13 的复核：

- Chrome 官方 Document PiP 文档：https://developer.chrome.com/docs/web-platform/document-picture-in-picture
- WICG 规范：https://wicg.github.io/document-picture-in-picture/
- WICG 透明窗口/鼠标穿透提案（议题不等于已支持）：https://github.com/WICG/document-picture-in-picture/issues/106
- WICG 排除整屏捕获中的 PiP（议题不等于已支持）：https://github.com/WICG/document-picture-in-picture/issues/114
- Jitsi 浏览器会议的 Document PiP：https://jitsi.org/blog/introducing-document-pip-for-browser-meetings/
- MiroTalk SFU `VideoDrawing.js`（检查的是会议视频层标注，不是任意原窗口覆盖）：https://github.com/miroslavpejic85/mirotalksfu/blob/ee47fb45fa1526f6166214ca423fa4ad1f6582f2/public/js/VideoDrawing.js

对可配合改造/允许嵌入的业务网页，业务页 SDK 或内嵌共享工作区仍是另一条路线；它不覆盖任意应用，且要业务系统安全和 SSO 配合，不作为本次通用小窗方案的前提。
