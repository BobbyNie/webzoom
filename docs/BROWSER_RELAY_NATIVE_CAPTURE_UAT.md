# 网页分流：原生标签页采集实测（2026-10-21）

> 后续已完成原生高动态性能修正及六观众持续共享、重复故障恢复实测，见 [追加实测](BROWSER_RELAY_NATIVE_PERFORMANCE_UAT.md)。下文保留最初两轮历史结果，不代表修正后的性能。

## 这次与此前测试的区别

这是本机的真实采集链路检查，不是多台实体电脑验收。独立打开 4 个现有的 Chrome / Edge 浏览器进程：1 位共享者与 3 位观众，每个进程使用独立临时资料。身份验证仍使用本地虚拟 OIDC，应用只监听 `127.0.0.1:20443`，没有连接、发布或修改公司环境。

- 调用应用原有的、浏览器原生 `getDisplayMedia`，不返回 `canvas.captureStream` 合成流，也不替换编码器、解码器或传输媒体。
- 共享的是专门创建的本地测试文档标签页，内容为普通 HTML、CSS 动画和时钟；不是用户的桌面、已有窗口、业务文件或摄像头/麦克风。原生标签页采集的画面再经过本项目真实 VP8 编码、WSS、网页同伴 DataChannel 和 WebCodecs 解码。
- 仅本轮共享者的隔离测试进程传入按完整标题自动选择此专用标签页的参数；不会在选择失败后改选整屏或其他窗口。**没有验证人工屏幕选择器、整屏共享或其他应用窗口采集。**
- 保留并检查 `getDisplayMedia`、`HTMLCanvasElement.captureStream`、`VideoEncoder`、`VideoDecoder` 与 `MediaStreamTrackProcessor` 的原生函数实现；观测代码仅记录真实 WebSocket 和 RTCPeerConnection 对象。

## 检查方式

1. 从专用标签页真实采集红、绿、蓝的 DOM 背景变化，在每位观众已经解码并绘制的画布上读取像素，逐个比对颜色；不是只检查帧计数。
2. 持续共享至少 60 秒，每 10 秒检查画面变化与解码进度；确认既有同伴连接不重建，同伴接收者不从服务器接收媒体。
3. 读取原生 `RTCPeerConnection.getStats()`，检查选中路径的两端协议为 UDP，且真实 DataChannel 有媒体字节流动。报告不保留候选 IP 地址。
4. 关闭整个网页转发节点浏览器进程，检查剩余两名观众自动重排成 1 个转发节点与 1 个同伴，随后仍收到新的画面颜色。
5. 停止共享，检查连接清理；再次调用原生采集接口开始新轮共享，检查接收端恢复。
6. 保存专用源标签页和同伴接收端截图、每阶段角色/计数、原生接口、浏览器版本与传输统计。

颜色确认耗时包含自动化调用和轮询，**不等于端到端媒体延迟**。普通 DOM 测试文档的复杂度也不代表高码率业务屏幕。

最终轮的具体证据：

- 原生 `getDisplayMedia` 从专用标签页采集，应用实际收到并编码约 `1920 × 984` 的画面；每个接收端的红、绿、蓝解码像素校验通过，源页面和同伴接收端截图均已保存并逐一查看。
- 稳定期转发节点解码帧数 `31 → 731`，两位同伴均为 `24 → 727`；已有同伴连接数未增加。两位同伴的服务器媒体接收字节始终为 `0`，同伴接收累计分别约 `7.30 MB` 和 `7.23 MB`（十进制）。
- 原生 RTC 统计显示选中连接两端均为 `host / udp`，转发节点的两个 DataChannel 各发送 `7,322,427` 字节，对应同伴各接收相同字节数。这是本机实际 UDP 同伴单播传输，**不是 UDP 广播或组播，也不是跨电脑网络证明**。
- 实际关闭整个转发节点浏览器进程后，剩余两位观众恢复为 `1 个转发节点 + 1 个同伴`，收到新的红色画面。关闭调用开始到角色重排及新像素确认共 `2,264 ms`；该数包含自动化等待，不等于精确断画时长或媒体延迟。
- 停止共享后剩余连接清理；再次原生采集，剩余观众收到新的绿色画面。
- 最终稳定期共享者与观众页面均显示约 `10 fps`，画质卡为“标准画质 / 1080p · 30 fps”。**卡片中的 30 fps 是配置目标，不代表实际达到 30 fps。** 共享者与观众都约 10 fps，不能据此把瓶颈归因于同伴转发；本测试没有隔离确认具体原因，也没有证明高动态内容流畅度达标。

## 如何复跑

需要本机已经安装 Chrome、Edge、原有 Node.js/Go 依赖，且按仓库约定完成构建。这个入口会打开可见的隔离测试窗口，结束时自动关闭；不会读取现有浏览器资料，也不安装软件。

在 `web` 目录运行：

```powershell
npm run build
npm run test:relay:native
```

- 新入口独立于默认功能、容量和持续共享测试，不默认在无桌面的 CI 上执行。
- 结果：`web/test-results/native-capture/results.json`，JSON 附件 `native-capture-report` 的 `body` 为 base64。
- 图片附件：`native-source`、`native-peer-received`。
- 原始采集受浏览器或系统策略阻止时应报告失败，不用合成流替代通过。
