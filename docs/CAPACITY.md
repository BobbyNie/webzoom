# 容量与质量验收

## 1. 验收条件

压力测试目标是 5 场会议，每场 200 名听众，持续运行 30 分钟。
这些数量不是日常业务上限。应用默认不限制会议数量和听众人数。
正常质量为 1080p、30fps、端到端画面延迟 p95 ≤ 1 秒。
码率降低、分辨率降低或帧率降低都必须单独记录，不能计为正常质量通过。

按每名听众 4–8 Mbps 估算，1000 名听众需要约 4–8 Gbps 的媒体出口。
网关、TLS 和网络协议还会增加开销。
资源配置必须覆盖应用、路由器、负载机、网络链路和浏览器设备。
不要在生产会议期间执行压力测试。

### 可选测试限制

仅在隔离的压力测试环境中设置：

```dotenv
LOAD_TEST_MAX_ROOMS=5
LOAD_TEST_MAX_VIEWERS=200
```

默认值均为 `0`，表示不限制。正值分别限制保留会议数量和每场连接容量（听众值加一名共享者）。
Docker Compose 从 `.env` 读取这些变量。OpenShift 测试部署可在容器环境变量中设置。
负数、非整数或整数溢出会使应用拒绝启动。
启用测试限制时，空会议也占用会议名额，直到主持人结束或自动过期。
测试结束后移除正值并重新部署。不要用测试限制管理日常会议。
修改容器配置需要重启；重启会中断会议和本应用会话。

## 2. 负载工具

```sh
go build -o bin/loadtest ./cmd/loadtest
```

工具只使用经过证书验证的 HTTPS/WSS，不提供跳过 TLS 校验的选项。
工具读取 JSON 字符串数组，内容为测试用户的 `__Host-webzoom-session` Cookie 值。
文件名建议使用 `artifacts/load.sessions.json`，并将权限设为 0600。

```json
["第一名测试用户的会话值", "第二名测试用户的会话值"]
```

**凭证警告：**此文件等同于测试用户的登录权限。
只使用经过批准的测试账号。不要复制同事的真实会话。
通过正常 OIDC 登录获取会话，不要在生产服务增加测试登录后门。
可使用组织已有的测试身份自动化，或在隔离浏览器配置中登录并导出 HttpOnly Cookie。
不要把 Cookie 放在命令行、报告、截图、工单或 Git 中。
测试结束后撤销这些会话，并删除凭证文件。

同一会议的身份必须不同。不同会议可以复用同一组身份。
工具仍要求按会议顺序展开完整数组。

### 合成转发测试

每场的第一项是创建者会话，后面是听众会话。
5×200 模式需要 1005 个数组元素。可以跨会议复用身份。

```sh
bin/loadtest \
  -url https://webzoom.example.intranet \
  -sessions artifacts/load.sessions.json \
  -rooms 5 -viewers 200 -fps 30 -mbps 6 -duration 30m \
  > artifacts/relay-result.json
```

此模式使用不可解码的合成负载。它只验证认证、WSS 和转发负载。
输出 `mode=synthetic-relay-only`，且 `render_latency_verified=false`。
它不能验证浏览器画面质量。
工具正常退出时会尝试结束自己创建的会议。强制终止时需要主持人手动结束。

### VP8 IVF 回放

`-ivf` 接受 VP8 IVF 文件。视频必须以关键帧开始，尺寸不能超过 1080p。
限制为 256 MiB、100000 帧、每帧不超过协议上限。
回放按 `-fps` 进行，不使用 IVF 时间戳。循环回放时从第一关键帧重新开始。
建议测试素材每秒至少包含一个关键帧。

```sh
bin/loadtest \
  -url https://webzoom.example.intranet \
  -sessions artifacts/load.sessions.json \
  -rooms 5 -viewers 199 -fps 30 -ivf artifacts/screen.vp8.ivf -duration 30m \
  > artifacts/ivf-result.json
```

每场预留一名真实浏览器听众，总数可以达到 200。
标准错误输出会显示会议链接。浏览器必须使用额外身份登录。
`-mbps` 不会重编码 IVF。必须另外核对素材的实际码率。
此模式支持实际解码抽样，但不能替代真实操作系统采集测试。

### 真实浏览器共享者 + 模拟听众

1. 使用五个真实浏览器创建五场会议。
2. 在每场会议中选择真实屏幕源并开始共享。
3. 为每场会议准备 199 名模拟听众和 1 名真实浏览器听众。
4. 将五场会议各自的 199 个会话按顺序放入 JSON 数组，共 995 项。
5. 将会议链接中的 ID 按相同顺序传入 `-join-rooms`。
6. 执行下列命令。

```sh
bin/loadtest \
  -url https://webzoom.example.intranet \
  -sessions artifacts/viewers.sessions.json \
  -rooms 5 -viewers 199 \
  -join-rooms '会议ID1,会议ID2,会议ID3,会议ID4,会议ID5' \
  -duration 30m > artifacts/browser-load-result.json
```

该模式只接收画面，不创建会议，不上传画面，也不结束主持人的会议。
只有全部模拟听众连接成功后，工具才开始 30 分钟计时。
当前只读模式的累计收帧指标也包含连接准备阶段收到的帧。计算吞吐时必须另外划分测量窗口。
真实浏览器必须在测量开始前加入。
需要更多真实浏览器样本时，相应减少模拟听众数，并保持每场总数为 200。
测试中进行 late-join 时，先让同一会议的一名测试听众退出，在启用测试限制时避免超过测试上限。

私有 CA 使用 `-ca /可信路径/ca-bundle.pem`。
不要把证书校验失败解释为网络容量不足。

## 3. 如何解释结果

- `frames_sent`：负载工具上传的帧数。只读模式为 0。
- `frames_received`：所有模拟听众收到的帧数总和。
- `bytes_received`：封包字节，不含 TLS/IP 开销。
- `sequence_gaps`：收到序号之间的缺口。不覆盖末尾丢失和未收到首帧的情况。
- `unexpected_disconnects`：非工具正常停止导致的读写失败计数。同一发布连接可能被读写路径各计一次。
- `receive_p95_upper_ms`：接收延迟的 100ms 分桶上界。60000ms 桶包括溢出值。
- `render_latency_verified`：始终为 false。此 Go 工具不执行浏览器解码和显示。

跨机器测试需要校准负载机与服务的时钟。
接收延迟统计只包含收到的帧。必须同时检查帧数、断线和丢帧。
工具退出码为 0 不是质量验收通过，只表示运行完成且没有检测到断线或零收帧。
不能只看 p95，而忽略大规模丢帧、低帧率或画质降级。

## 4. 真实画面验收步骤

1. 记录浏览器、操作系统、硬件、容器 CPU/内存、网卡和 Route 版本。
2. 使用浏览器信任的真实证书及真实 Keycloak。
3. 通过实际 Nginx 或 OpenShift Route 访问服务。
4. 在每个共享源中显示毫秒时钟、滚动文字和移动图形。
5. 每场至少抽样一台独立真实浏览器。必须包含 Chrome 和 Edge。
6. 用时间同步的仪器或同画面录像比较源画面和听众画面。
7. 连续保存延迟样本、实际尺寸和帧率。不要只保存平均值或单张截图。
8. 检查每场 p95，并保留原始样本。界面估算值只作诊断参考。
9. 在全负载状态下持续运行 30 分钟。
10. 核对五场均维持正常档位、1080p 和 30fps。
11. 另外执行晚加入、转交、停止、重新共享和短时断网。
12. 检查浏览器权限和媒体轨道，确认没有音频、麦克风或摄像头请求。
13. 检查浏览器网络日志及网关抓包，确认业务请求只有 HTTPS/WSS。

本机无头浏览器的 Canvas 来源不能替代操作系统采集授权。
实际浏览器中还要验证切换到被共享窗口、切换标签页和浏览器最小化后的行为。
浏览器或系统可能暂停被遮挡、锁屏或最小化的采集源。应记录这种限制。

## 5. 拥塞和隔离测试

1. 先保存正常网络的基线。
2. 只对一名听众限速和增加延迟。不要限制整个共享服务。
3. 检查该听众恢复到关键帧，或被写超时断开后重连。
4. 检查共享者降档，且所有界面显示正确档位。
5. 检查其他会议的帧率和延迟。
6. 恢复网络，观察每 30 秒最多恢复一档。
7. 监测 RSS、Go 堆、容器内存、队列长度、出口和连接数。
8. 检查长期运行时内存是否稳定，而不是仅验证队列单次上限。

应用队列理论上限为每听众 8 帧、2 MiB。
操作系统 socket、TLS、网关和浏览器也有缓冲。必须一起观测。
单路编码意味着慢听众的反馈可能降低本场会议所有听众的画质。
其他会议不应受到网络写入阻塞。

## 6. 未达标处理

报告必须包含具体瓶颈，例如网关 CPU、服务锁竞争、出口带宽、编码能力或浏览器解码速度。
需要改动资源或设计时，重新运行同一基线。
禁止将自动降级、只建立连接或本机环回测试标记为正式容量验收通过。
