## 交付状态和发布路径

代码通过本机检查不等于已发布镜像。本轮没有直接修改公司 OCP、JFrog、SSO 或持久卷。

领导现有工作流支持在选定副分支上手动运行，先执行质量检查、Linux 镜像构建、漏洞扫描和容器部署测试，成功后产生 `tested-container` 中的 `webzoom.tar.gz`、`image-id.txt`。仅 push 普通副分支不会自动触发现有工作流；可以手动触发或通过 PR 触发检查。不能为拿到镜像而合并 main 或打领导的 `v*` 标签。

后续发布时必须：

1. 明确推送本功能分支，不能依赖当前跟踪分支执行无参数 push。
2. 在该分支的固定提交上运行现有工作流，确认质量与镜像两个 job 都成功。
3. 下载**同一轮测试过的镜像**，记录产物提交 SHA、工作流 run、SHA-256、image ID；校验下载文件后再搬运。
4. 如需 GitHub Release，创建名为 `pip-uat-main-2fc3046-r2` 的 **prerelease**，指向本功能提交，并附该轮镜像包、校验和及说明。不要标为最新正式版本，不上传源码 ZIP 冒充镜像。
5. 公司批准的 Linux/Podman 机器解压加载、核对 image ID，tag 成唯一 JFrog 测试标签并 push。实际 load 后的镜像名以输出为准，不能猜 `webzoom:local` 的拼写。记录 push 后的 registry digest；它不等于 image ID。
6. 不把访问令牌写入公开命令、文档或 Release。公司 TLS 和凭据处理沿用已确认的公司流程；不改 OCP 全局 registry 信任策略。

尚未完成上述步骤时，不能把任何候选镜像地址当作已存在、可拉取镜像。本文件不提供未核实的镜像更新命令。

## OCP 原则

沿用当前成功的 `webzoom-uat` / Deployment `webzoom`，只更新经过确认的容器镜像，不重新创建整个部署。
更新前记录当前实际镜像、成功 revision、rollout 状态，预约 UAT 中断窗口。保留 `/data` 的 `webzoom-data` PVC、`/etc/webzoom/trust` 挂载及现有环境变量、Secret、Service、Route、SSO 回调、单副本/Recreate 配置。

需要更新/回退时先取得集群当前只读输出，再给可直接复制的命令；不要要求用户猜参数，更不要把旧失败的小窗部署模板拿回来覆盖。已保存的带宽配置仍在持久卷上，回退前评估兼容性；切换镜像不等于备份数据。

## 双账号验收

1. 两个不同 SSO 账号入会；未授权者不能画线或发送指示。主持人授权后才能操作。
2. 共享者打开小窗，真正切到 Excel/PPT，另一账号画圈和移动光标；在小窗内看到相同位置和正确姓名。
3. 测完整画面、跟随 ×2、仅标注、改窗口尺寸和全屏；检查比例、边缘指示、笔迹清除、连续多笔和迟到参会人回放。
4. 撤销批注立刻禁止新批注；转交共享不自动授予批注。停止、结束会议、断网、过期、关闭页面后不能留下失效反馈。
5. 关小窗仍共享，重开可恢复；小窗“停止共享”真正停止所有共享轨道。
6. 分别真实共享业务窗口、浏览器标签、整个桌面。整屏情况下检查窗口入镜和递归风险，必要时使用仅标注或第二块屏幕。
7. 普通用户访问 `/admin` 仍受限；原管理员功能、带宽上限设置及重启后恢复、SSO 自动续期、证书信任、只读根和任意 UID + PVC 均需回归。
8. 公司浏览器不支持或策略禁用 API 时明确提示，不能影响正常共享；不要求用户安装原生助手。

自动浏览器测试使用签名 OIDC fixture 和 canvas 合成共享流：验证真实 WSS、浏览器解码和 Document PiP，但不能替代真实公司 SSO、OS 屏幕选择器、Windows 桌面置顶和 OCP/PVC/任意 UID 实测。性能与百人容量未因此获得保证。

1. 一个主持人、至少三名观众进入同一会议（可在开始共享前申请）。A 申请后，A 显示等待，主持人看到 A；此时 A 不能画画。
2. 主持人拒绝 A 后，A 恢复可申请；A 再申请，主持人单独同意，A 可使用画笔/姓名指示光标。

4. A 申请后取消，主持人列表随即移除；申请人离会/断线/登录失效也移除。重新加入必须重新申请。
5. 主持人刷新重连，仍能看到在线人的待处理申请；开始/停止共享或转交共享权不隐式批准申请。
6. 回归既有主动授权/撤销、主持人批注、共享者反馈小窗、SSO、管理员和带宽持久化。

## 2026-10-23：背景觀眾重連修復（本機候選，尚未發布或部署）

- 新網頁使用 `mediaAck=1` 與累計 `media-ack`。每連線最多 4 個未確認媒體訊息，配合既有有界佇列丟棄舊畫面；停頓恢復後請求關鍵幀。控制訊息不消耗此視窗。舊用戶端仍可連線，但沒有新背壓保護，升級後須重新載入網頁。
- 同帳號、同有效 session、同會議/共享 epoch 的觀眾，非明確退出的短暫斷線可於 30 秒內恢復已授予的批注權限。待審申請不恢復。超時、不同 session、主持人撤權、停止/轉交共享、結束會議、登出均不可恢復；共享者本身不自動恢復共享。
- 「離開會議」先送出明確 leave，故重新進入仍須重新授權。短暫斷線在主持人名單仍可能顯示離開/加入；此修復不承諾所有網路中斷無感。
- 仍連線的會議由伺服器協助續期，不再只依賴頁面計時器；頁面恢復時也立即檢查。無會議連線的閒置首頁不因此自動續期。
- HttpOnly/Secure opaque session Cookie 保留至既有固定 8 小時上限，以便 WebSocket 續期後頁面恢復能找回同一個 session；這不是授權期限延長。每次請求仍驗證服務端真實 token/session 截止時間，無 refresh grant、真實過期、撤銷、登出及固定上限都不能繞過。舊登入的 Cookie 不會被憑空延長，升級驗收請重新登入。
- 暫時網路或身份服務故障顯示不可用並重試；確認 401/invalid_grant 才按失效處理。不可因此讓真正過期的登入繼續操作。

驗收需包含：共享中分流開/關各暫停觀眾執行後恢復、強制斷線重連、明確離會重進、離線期間撤權、30 秒恢復窗口邊界、不同 session、停止/轉交/結束會議、登出及固定上限。簽名本機 OIDC 與合成共享流不能替代公司 SSO/瀏覽器策略/網路實測。

### 2026-10-23 補充邊界修復（同為未部署候選）

- 已送出的登入憑證輪換不因單一 HTTP/WS 請求取消而丟棄結果，最多仍受 15 秒操作逾時限制；尚未開始的取消請求不啟動輪換，登出/真實過期/固定上限仍不可復活。離會後不再發起新的會議續期，但已開始的輪換可完成保存。
- WS 握手失敗不視為主動離會，不會吃掉同一 session 的短暫重連批注恢復資格。
- 主動離會等待 HTTP 最多 2 秒；失敗時嘗試既有 WS leave，之後返回首頁。開始離會就停止自動重連，避免通知尚未完成時又進入會議。完全斷網時，遠端不可能立即收到退出通知，仍須依實際斷線/恢復窗口處理，不承諾已送達。

補充驗收：憑證輪換途中關閉 WS/HTTP 與登出；握手失敗後有效重試；離會 HTTP 懸掛但 WS 正常、離會 HTTP 延遲期間 WS 斷線；確認沒有卡在會議頁、未自動重連、已送達的明確離會不恢復舊權限。

### 2026-10-23 共享非同步操作與恢復期限修復（本機候選，未發布/部署）

- 選屏及啟動共享綁定當時的連線、操作版本與共享 epoch；等待途中斷線/重連、離會、共享權或 epoch 改變，舊操作只清理自己的擷取流，不得套用至新連線。
- 開始/停止共享 API 可攜帶 `epoch` 作為條件；伺服器在同一把狀態鎖下比較，不符合回覆 409 且不更動會議。舊客戶端省略此欄位的相容行為不變；完整保護需要新版前後端及重新載入網頁。
- 延遲的開始共享 HTTP 回覆不得覆蓋較新的 WS 會議狀態。舊共享的結束通知、編碼錯誤及失敗清理不得停止新共享；自動停止攜帶其所屬 epoch。
- 同一斷線期間，多次失敗的 WS 握手保留原批注恢復截止時間，不得每次重試延長 30 秒。真正建立連線後再次斷線，才可按新的斷線重新給予恢復窗口；其餘同 session/epoch、撤權、登出等邊界維持不變。

新增自動驗收：選屏未完成即斷線並重連、開始共享回覆延遲到下一輪共享後才到、舊擷取流結束通知延遲到新共享後才執行；另測試舊 epoch 的開始/停止不影響新共享、失敗握手不能推遲原截止時間及成功重連後的新恢復窗口。使用本機真實 TLS/WSS/瀏覽器與合成 canvas，不代表公司實際瀏覽器策略、擷取 UI 或網路驗證。


### 2026-10-23 共享請求結果不明與清理確認（本機候選，未發布/部署）

- 開始共享的 HTTP 請求等待最多 10 秒。超時或回覆遺失時，停止本次擷取資源，並使用本次操作所屬的 WS 連線取消啟動；不是只中止瀏覽器的等待，因為已送出的請求仍可能被伺服器執行。此期限不強制關閉瀏覽器原生選屏視窗。
- 伺服器在同一狀態鎖內處理帶原始 epoch 的 `cancel-start`：若啟動尚未執行，先推進 epoch 阻止舊請求；若已執行，只停止該次啟動。重複或晚到的取消不得停止後來的新共享。WS 控制另須比對目前真正的 Peer，觀眾、已移除的舊連線或缺少 epoch 的請求不可越權清理。 取消後亦須重新發送已停止的分流規劃及清空的批注狀態，避免只改了會議 active 卻留下舊同伴連線或標記。
- 停止共享先立即停止本機擷取；HTTP 最多等待 2 秒，失敗或超時則用原連線送帶共享 epoch 的 `stop-sharing`。晚到的舊 HTTP 停止必須回覆 409，不能停止新的共享。
- 備援清理須等待伺服器「已處理」確認，最多 2 秒；在確認前不解鎖這次操作的按鈕，避免取消仍在路上就立即重試。確認表示命令已處理（可能因狀態已更新而無需動作），不是保證任何舊 epoch 都會被停止。確認遺失、連線已關閉或超時時，只關閉本次操作的原連線，走既有斷線清理/重連，不把無法確認的通知當成成功送達。
- 完整保護需要新版前端與後端一起更新，並重新載入網頁。斷網時仍不可能保證遠端立即收到停止通知；共享者重連後仍須主動重新選屏。不改動登入有效期、批注 30 秒恢復邊界或明確離會/撤權規則。

補充驗收：伺服器已啟動但 HTTP 回覆遺失；開始請求卡住後資源釋放與舊請求 409；停止 HTTP 失敗/卡住但 WS 正常；下一輪共享開始後才放行舊停止請求（409 且畫面繼續）；暫扣取消通知時按鈕不提前解鎖；控制確認逾時僅淘汰原連線；錯誤使用者與舊 Peer 無法停止新共享。瀏覽器測試使用本機真實 TLS/WSS、簽名測試 OIDC 與合成 canvas，不能替代公司 SSO、真實選屏、作業系統節流/休眠或跨網段現場驗收。


### 2026-10-26 重連建立階段卡住（本機候選，未發布/部署）

- 會議資料查詢與 WebSocket 握手各有 10 秒等待上限；超時後取消本次等待/淘汰本次尚未建立的連線，進入既有最多 8 次、帶抖動的重試流程，不能因單次請求無回應而永遠停在「正在重新連接」。瀏覽器完全凍結或休眠時 JavaScript 計時器仍可能延後，不承諾此時的牆鐘 10 秒上限。
- 會議生命週期清理會中止未完成的查詢、清除握手計時器。舊連線的遲到 open/message/close 不得覆蓋或清掉目前連線；握手逾時前會再檢查 readyState，不淘汰實際已連上的 OPEN 連線。
- 不延長登入期限或批注 30 秒恢復窗口，不自動恢復共享者的擷取；恢復仍須符合既有同 session/epoch、未撤權等規則。長時間斷網仍可能需要重新授權。
- 自動驗收包含：重連查詢無回覆、真正原生 WebSocket 握手無回覆、遲到舊查詢與舊連線事件、成功/失敗/生命週期取消時的計時器清理，以及雙帳號觀眾的影片恢復與獲授權後真實批注送達。握手卡住的端點僅存在於帶 testtools 標記的本機測試服務，不在正式服務新增此路由。

以上使用本機 TLS/WSS、簽名測試 OIDC 與合成 canvas；不是公司 SSO、真實選屏、自然背景節流/休眠或跨網段測試。驗證記錄存於本機 artifacts/reconnect-deadline-verification-20261026，實際通過項目以該次報告為準。
