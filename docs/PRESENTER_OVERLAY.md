# 共享者原屏幕批注助手（Windows 实验版）

> 历史方案：当前纯 Web 小窗分支已移除主界面的助手配对入口。新部署请看 [共享者反馈小窗](PRESENTER_FEEDBACK.md)，不需要运行本助手。以下内容仅供旧实验版维护参考。

> 分支：`feature/presenter-overlay`。这是待公司 UAT 验收的功能，不是对所有机器已验证的正式版。
> 不改 main、不覆盖正式镜像、不自动部署 OCP。原来的纯网页批注仍可独立使用。

## 1. 解决什么问题

参会人在 WebZoom 中画线或移动指示光标时，共享者不用切回 WebZoom，就能在正在操作的业务网页、Excel、PPT 上看到反馈。

采用“网页会议 + 共享者本机免安装助手”，不是 Chrome 扩展：

```
参会人网页 --已有批注通道--> WebZoom 服务端 --只读 WSS--> 共享者 Windows 助手
                                              透明批注窗口覆盖选中的显示器
屏幕视频仍使用现有 WebZoom 视频通道，不经过助手
```

- 主持人仍在网页逐人授予/撤销批注权；助手不能给人授权、画线或远程操作电脑。
- 只有需要在原屏幕看批注的共享者运行助手。普通参会人不安装任何东西。
- 不新增本地端口、驱动、服务、浏览器扩展、开机启动或系统注册。双击 EXE，以普通用户运行。
- 不新增 SSO client、环境变量、OCP SCC 或管理员权限。需要同一提交构建的新服务端镜像和新助手。
- 此功能不解决视频带宽问题，也不包含此前讨论的 UDP/LAN 转发。

## 2. 第一版的明确边界

| 项目 | 本版范围 |
| --- | --- |
| 系统 | Windows x64；Windows 10 build 19041（2004）及以上或 Windows 11 |
| 浏览器 | 现有 WebZoom 支持的桌面 Chrome/Edge；需可信 HTTPS |
| 共享方式 | **只能共享整个屏幕/整块显示器**，不能选某个窗口或标签页 |
| 显示器 | 助手手动选择与浏览器共享的同一块显示器；一场会议同时一个助手 |
| 坐标 | 比较捕获画面与显示器宽高比，允许等比降采样；同宽高比的多块显示器无法据此自动辨别 |
| 内容 | 画线、带姓名的指示光标、清除；不修改原文件、不编辑 PPT、不是远程控制 |
| 滚动 | 批注固定在屏幕坐标，不跟随滚动后的段落或移动后的窗口；换内容后请清除旧批注 |
| 普通应用 | 目标是普通桌面网页、Excel、PPT；不承诺覆盖 UAC 安全桌面、独占全屏游戏、受保护视频或特殊虚拟桌面 |
| 安装权限 | 程序设计不要求管理员；公司应用白名单、签名、EDR 管控仍需要 IT 批准，不能绕过 |
| 外观 | 首版为英文提示的控制台助手，附中文步骤；非完整会议桌面客户端 |

Windows 的捕获排除 API 成功，不代表所有浏览器版本、RDP/VDI、录屏工具都必然排除该窗口。**实际 Chrome/Edge 整屏捕获不重影，是上线前必须完成的 UAT，不可以省略。**

## 3. 操作步骤（共享者）

### 准备

1. 维护人员先将同一提交的测试镜像部署到 UAT；不要把旧 v0.1.4 或旧批注镜像与本助手混用。
2. 从维护人员或该分支的 GitHub Actions 获取 `presenter-overlay-windows-x64` 附件并解压到有写入权限的个人目录。
3. 包中包含 `WebZoomOverlay.exe`、本说明、`BUILD.txt` 和 `SHA256SUMS.txt`。核对来源与哈希；本版未签名，若公司阻止运行，请走审批，**不要关闭防护或使用管理员绕过**。
4. 浏览器能打开 WebZoom，不代表原生助手信任同一证书。助手使用 Windows/Go 的系统信任和严格 TLS 校验；公司 CA 必须按 IT 认可的方式配置信任，不能跳过验证。

### 每次会议

1. 登录 WebZoom，开始共享，在浏览器选择 **整个屏幕**。
2. 双击 `WebZoomOverlay.exe`，不要选择“以管理员身份运行”。
3. 助手列出显示器编号、分辨率、位置。输入与你共享相同的显示器编号，按 Enter。它会停在粘贴配对信息的位置。
4. 回到 WebZoom，在“在原屏幕上看批注”中点击 **生成助手配对信息**，然后点 **复制配对信息**。
5. 在助手中粘贴并按 Enter。**粘贴不显示任何字符是正常安全行为**，不是没粘贴。
6. 配对信息有效期 60 秒，只能用一次。过期、用过或连接失败时，重新运行助手并生成新的配对信息；不要将它发给其他人或上传日志。
7. 会议发起人给参会人批注权；你切回 Excel/业务网页，由参会人在 WebZoom 中画线或指示。
8. `Ctrl+Alt+Shift+F8`：暂时隐藏/重新显示本机批注；`Ctrl+Alt+Shift+F9`：断开助手并清除本机批注。结束后按 Enter 关闭控制台。也可以在网页点“断开批注助手”。

网页显示“配对信息已生成”不等于助手已连上。首版不提供网页实时连接状态；请用一笔测试批注确认。若切回 WebZoom 预览本身，建议用 F8 暂时隐藏本机层，避免预览内的批注与桌面层同时出现。

助手是只读的。按 F8 仅隐藏本机反馈，不会清除参会人看到的画线。不要点击控制台内容进入文本选择/暂停状态，保持它最小化或在后台运行。

## 4. 连接和安全机制

- 只有**当前正在共享的浏览器会话**可以生成配对信息；同一用户在另一会话登录也不算同一个共享连接。
- 配对接口复用现有登录、Origin 与 CSRF 检查，验证 room、user、session、共享 epoch 和整屏捕获参数。
- 单次能力凭据使用 32 字节安全随机数；服务端只存 SHA-256 摘要，60 秒过期，最多 1024 个待配对项。生成新凭据替换同会话的旧凭据。
- 网页遮蔽凭据，原生控制台关闭输入回显，避免整屏共享时读到它；剪贴板仍属于本机安全边界，请勿外传或开启不受控同步。
- 助手通过 WSS Authorization 头提交凭据；不放在查询参数、不接受重定向、不禁用证书校验、不保存 SSO 密码/登录 token、不监听 localhost。
- 助手连接只读：收到客户端业务消息就断开。不计入会议参与者，不订阅视频。慢助手只断开自己，不拖垮参会者。
- 心跳每秒检查浏览器会话和共享连接。停止/转交共享、结束会议、共享者离开或会话撤销时断开。续期沿用服务端现有会话逻辑，助手不能自己延长登录。
- 网络接收超时为 4 秒，失败后清空并关闭透明窗口；正常调度下通常在这个量级内退出，不能作为进程被系统冻结时的硬实时保证。
- 显示器布局/DPI 改变、锁屏、会话断开、休眠时终止助手；不自动重连，避免继续在错误的显示器上画。
- 指示光标约 1.8 秒无更新即消失；画线和事件受已有房间上限、严格坐标/颜色/epoch/generation 校验限制。
- 透明窗口设置不激活、置顶、鼠标穿透；调用 `WDA_EXCLUDEFROMCAPTURE` 防止二次捕获。API 不可用时拒绝启用，不退化成可能遮屏的模式。
- 原生画面只在批注变化/光标过期时重绘，不因为每秒心跳重复绘制整个显示器。

## 5. 维护人员构建、交付和回退

### 本地助手

Windows x64、PowerShell 7、与 go.mod 一致的 Go 工具链：

```powershell
go test ./...
go vet ./...
./scripts/package-overlay.ps1
./artifacts/presenter-overlay-windows-x64/WebZoomOverlay.exe --self-test
```

脚本只生成附件目录，不安装任何东西。`BUILD.txt` 标记源码提交和是否包含未提交修改。`--self-test` 创建隐藏窗口检查本机 API，不连接服务器，也不证明真实浏览器的捕获排除效果。

### GitHub Actions

1. 只推 `feature/presenter-overlay`，在 `Test and publish container` 中手动选择该分支。
2. **quality、image、overlay-windows 全部通过后**，从同一次运行下载：
   - `tested-container`：解压得到 `webzoom.tar.gz` 与镜像 identity，供公司 Linux 导入后转存 JFrog。
   - `presenter-overlay-windows-x64`：仅共享者的 Windows 附件。
3. `tested-container` 沿用现有 1 天保留期，请及时保存；助手附件保留 14 天。不要混用不同提交的镜像和 EXE。
4. 本分支运行不触发正式 publish；不创建正式 v* 标签、不覆盖 v0.1.4。若需要 GitHub Releases 长期分发，应另建明确标注 UAT 的预发布，不宣称正式版。
5. 公司镜像流程继续按 `docs/ANNOTATION_UAT.md` 的保存旧 digest、导入、重打唯一 UAT 标签、推 JFrog、更新 UAT Deployment 流程走。镜像地址必须使用真实推送成功的地址，不猜版本号。
6. 更新服务端会重启单副本并中断进行中的会议，请安排测试窗口。助手不需要装到 OCP，也不应放进 Linux 容器。

回退：先退出助手，将 Deployment 镜像改回本次更新前保存的**精确镜像 digest**并确认 rollout 成功。原生助手没有数据库迁移、服务注册或系统安装，退出后不再覆盖屏幕；旧服务端没有配对 API，不能继续连接新助手。

| 隐私 | 共享画面上看不到网页配对明文，粘贴到助手也不回显；日志中不留凭据 |

## 7. 为什么不是只修改网页或只做 Chrome 插件

普通网页的叠加层只属于它自己的页面，不能直接覆盖另一应用的 Windows 窗口。Chrome 扩展注入网页也不等于能覆盖 Excel/PPT。当前需求明确包含原工作屏幕，所以采用最小权限的 Windows 助手；不是声称知道 Zoom/Teams 的私有源码，也不是做完整桌面会议客户端。

- Microsoft Extended Window Styles: https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles
- Microsoft Layered Windows: https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features
- Microsoft per-monitor DPI: https://learn.microsoft.com/en-us/windows/win32/hidpi/dpi-awareness-context
