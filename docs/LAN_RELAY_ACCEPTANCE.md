# LAN 中继：验证计划与上线门槛

- 日期：2026-10-12；对应[方案](LAN_RELAY_PROPOSAL.md)与[事实复核](LAN_RELAY_VERIFICATION.md)。
- **当前所有G0–G4均未执行。** 本文件是测试计划，不是测试结果。
- 测试必须在获批的隔离环境和试点设备进行；不得在正在使用的办公广播域直接压测。
- 数值为建议验收起点，须结合批准的终端型号、浏览器版本、实际网络与业务画质确认。改动门槛要记录原因，不得在测试失败后悄悄放宽。

## 2. G0：普通用户安装与真实广播能力

**目的：先证明公司电脑允许这条路线，再开发完整媒体协议。** 至少两台真实Windows电脑；防火墙/EDR保持开启。允许IT提前配置批准的规则，但测试用户不得提权。

| ID | 操作 | 通过证据 |
| --- | --- | --- |
| T01 | 用标准用户安装、启动、升级、卸载helper | 无UAC提权；无HKLM、服务、驱动或系统目录写入；卸载清理自己的HKCU/用户文件 |
| T02 | 经批准渠道安装扩展并连接host | 固定扩展ID；`connectNative`成功；重开浏览器仍可用 |
| T03 | 用不获准网页/另一个扩展尝试连接 | 全部拒绝；不执行任意命令或打开任意网络目标 |
| T04 | A机向批准接口广播，B机接收 | 使用真正的IPv4广播目的地址；不是为B单独建立一条媒体单播 |
| T05 | 两个不同广播域各自探测 | 只形成实际可达分组；无跨网段广播路由依赖 |
| T06 | 测防火墙未放行/显式阻断/profile变化 | 明确失败；不提示用户关防火墙、不试图提权添加规则 |
| T07 | 接入VPN、第二网卡、网卡切换 | 仅批准接口发送；接收能核对接口；旧接口路径及时撤销 |
| T08 | 相同私网prefix但不互通、非/24掩码、终端隔离 | 不误合并组；组播/广播差异不被隐藏 |
| T09 | 第二profile、第二host、其他进程占用端口 | 不抢占、不混流；错误可见；退出后资源释放 |
| T10 | 终止helper或浏览器、进入睡眠 | socket释放或有明确退出期限；无长期孤儿播发进程 |

阻断条件：需本地管理员才能安装/运行；无法取得获批扩展渠道；用户级host被禁止且无批准变更；局域网广播被禁止且业务不接受替代方案。出现阻断立即记录，不用安全绕过继续。

## 3. G1：网页↔扩展↔helper媒体桥

至少在一台代表性公司电脑上测试发送与接收两方向，再两机端到端。使用真实VP8和WebCodecs，不把随机二进制吞吐当作画面质量通过。

| ID | 场景 | 通过标准/测量项 |
| --- | --- | --- |
| T11 | 正常码率和关键帧突发 | 覆盖现有1.2/1.8/3/4/6 Mbps档位；至少最高目标持续30分钟；记录实际码率、帧率、清晰度 |
| T12 | 最大1 MiB原始帧及签名外壳 | 双向正确分块/重组；每条JSON≤96 KiB；无Native Messaging超限断开 |
| T13 | 缺块、重复块、非法索引、超大总长 | 拒绝或限时丢弃；内存有界；不能越界或无限等待 |
| T14 | 网页/扩展/host一方消费变慢 | credit生效；显式降级；队列不无限增长；控制与撤权不被媒体饿死 |
| T15 | 后台标签页、窗口最小化、长时间静置 | 使用真实Chrome验证媒体与租约；不能靠前台demo宣称后台可用 |
| T16 | helper崩溃、MV3重建、网页刷新 | 恢复握手和版本检查；旧帧不进入新会话；不产生重复host |
| T17 | 两场会议、扩展/host版本不匹配 | 正确隔离；资源超限/不兼容明确拒绝；不中断其他健康会议 |
| T18 | SSO经历多次短令牌续期 | 至少跨3次实际令牌期限且总时长≥30分钟；画面不断流，采集权限不重问 |

建议性能门槛：支持的最高档位下，新增本地桥延迟p95≤100 ms（双方向分别测量）；端到端画面延迟p95≤1秒；无无界队列或持续内存增长。辅助程序+扩展CPU/峰值内存必须记录并由终端团队确定可接受上限，未明确上限前不算完成容量验收。OS峰值RSS和原始重组配额不是同一个指标。

测时须说明时钟方法；跨机时钟偏差不能冒充视频延迟。可使用同机组件时间戳测局部耗时，并通过同步的可视计时画面/经校准的时钟测端到端。发布脱敏统计，不上传会议内容。

**G1不通过：先重做媒体桥设计，不进入大规模开发。** 不用关闭浏览器安全机制或自动增加OCP直连代替通过。

## 4. G2：单组完整媒体与安全

先冻结外层字节布局、长度预算、版本协商和测试向量，再开发。协议样例仅包含虚构身份和测试密钥。

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| T19 | 一共享者、一中继、多接收者 | 只有中继收到OCP下行媒体；所有观众控制连接仍有效；原WZ01解码可复用 |
| T20 | 新观众进入、共享开始/停止/转交 | 能及时获取关键帧；旧epoch、旧签名封包不会混入新画面 |
| T21 | 边界帧和UDP封包 | raw≤1 MiB、签名外壳≤2 KiB；UDP payload≤1200字节；分片数≤2048；协议字段和限制互相一致 |
| T22 | 丢包、乱序、重复、延迟、截断 | 无崩溃/无限分配；正确丢弃依赖帧；请求关键帧限流；记录画面恢复时间 |
| T23 | 伪造房间/group/generation、错误AEAD或签名 | 全部拒绝；包括“持有组密钥的恶意成员伪造共享者帧” |
| T24 | GCM nonce、并发发送、进程重启 | 同key无nonce复用；重启重新取得generation/key；越界或旧key拒绝 |
| T25 | 当前接收者注销/会话到期/被撤销 | 服务端获知失效后轮换；保留旧key的独立测试接收器不能解密后续新流 |
| T26 | 新成员拿到新key后回放旧录包 | 无法解密旧generation媒体；不承诺擦除老成员已保存的历史画面 |
| T27 | native/control连接断开，helper保留旧包重放 | 租约/epoch/key fencing生效；合法客户端fail closed；未知实例拒绝 |
| T28 | 畸形JSON/长度前缀/UDP头的自动化fuzz | 有界解析；stdout只输出协议；日志不出现key、Cookie或媒体 |

建议恢复门槛：新加入后正常网络下首个可解码画面p95≤3秒；普通丢帧后可解码画面恢复p95≤2秒。这些不是先验保证，丢包矩阵须测试0%、0.1%、1%、3%随机丢包及100–500 ms突发丢包；记录各档位可用边界，不把3%丢包下仍流畅当默认事实。

签名计算应在Hub锁外的有界worker中进行，并在输出前重新校验会议epoch/当前发布者，测试并发转交与签名任务完成的竞态。上行、下行、IPC和UDP分别设置大小上限，不能统一放宽现有读取限制。

## 5. G3：多组、中继故障和20 Mbps预算

至少两个真实广播域，每组至少一中继和一接收者。虚拟VLAN/合成负载可以补充算法验证，但不得冒充实际交换网络、无线或公司终端验收。

| ID | 场景 | 通过标准 |
| --- | --- | --- |
| T29 | 两组运行，增加每组观众 | 媒体订阅仍为每组1份；按同一输入录像比较媒体出口，差异≤10%；控制流量单独计量 |
| T30 | 增加第三/更多组及并发会议 | 出口随实际订阅数增长并符合预算；不会把“媒体不随人数增长”误解为不随组数增长 |
| T31 | 强制关闭中继、拔网线、睡眠、切换接口 | 自动重选；重新确认覆盖；旧generation无效；建议恢复p95≤10秒，未达标如实记录 |
| T32 | 单向可达、旧中继与服务器隔离 | 不假设可达性对称/传递；不在同一组留下无法收到新中继的成员 |
| T33 | 大量成员同时进出 | 探测、关键帧、租约和换key有界；控制消息不超限；无重选/换key风暴 |
| T34 | 预算边缘增加组、回退、关键帧突发 | 先拒绝/降级，不无条件放流；例：6 Mbps × 3组已达18 Mbps媒体，不能忽略开销 |
| T35 | 同组故意阻断广播并请求直连 | 无预算不得回退；明确错误；无全员回退导致出口暴涨 |
| T36 | 低速消费、慢服务器写入与pacing | 有界队列；不阻塞全局Hub；保留控制带宽；画面过期机制可正常恢复 |
| T37 | 共享者原本是中继后获得共享权 | 重新安排下行中继，不重复下行自身媒体；新epoch正确 |
| T38 | OCP重启、旧helper继续运行、回滚 | 旧实例权限失效；按既有行为重新登录/建会；回滚先暂停媒体再核算直连预算 |

容量必须同时记录：应用媒体字节、OCP/路由器/受限链路字节、上下行方向、采样窗口、协议重传、控制/密钥、实际画质。媒体字节不等于线速字节。

20 Mbps硬上限的验收口径由网络团队定义。推荐在实际计量点记录1秒和10秒窗口并分析短时burst；若平台有整形，再记录排队/丢弃和用户体验。应用不应承诺自己控制不了的其他共享业务流量。

若只允许预算内总媒体16 Mbps作为试验起点，准入器要拒绝预计超过它的请求；该阈值不得在README中写成已经生效的配置。

## 6. G4：试点和发布门槛

全部满足才可以对领导报告“已在批准范围验证可用”：

- [ ] G0–G3附有设备、版本、日期、真实结果与异常记录；失败项未被省略。
- [ ] 公司批准扩展分发、用户级host、签名程序、接口/端口和必要防火墙规则。
- [ ] 用户安装/升级/卸载无管理员权限；程序没有通过系统服务暗中提权。
- [ ] 密码封包、nonce、密钥轮换、来源签名、扩展origin边界通过安全评审。
- [ ] 对支持的组数、人数、并发会议和码率写出明确容量范围与不支持场景。
- [ ] 试点至少连续2小时，并覆盖短令牌多次续期；另测8小时应用上限附近的正常到期行为。
- [ ] 多会话/组变化下，无持续资源泄漏；CPU/内存上限已经由终端团队确认并达标。
- [ ] IT确认广播/风暴抑制对非参会设备和其他业务无不可接受影响。
- [ ] 有分阶段启用、关停、安装包回滚、有限直连、数据保留和故障联系人说明。
- [ ] 当前OCP不增加特权、不开放未经审批的UDP入口、不增加不受支持的多副本。
- [ ] 不把未经测试的Edge、Wi-Fi、VPN、IPv6、未托管设备列入支持清单。
